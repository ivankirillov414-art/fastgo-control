# FastGo: семь суточных резервов, 7 ноября 2026

Поручение: полный перенос на собственный хостинг с адресом fastgo.velo56.ru; независимо от готовности нового сервера — проверяемые суточные копии на сервере и во всех используемых приложениях. Новый сервер пока не заказан. Нельзя переключать рабочую базу на неподготовленный сервер.

## Политика

- День определяется в Asia/Yekaterinburg; сохраняем последние **7 успешно завершённых суточных дат**, а не удаляем по возрасту, если новые копии не созданы.
- Не удалять старый резерв до успешного завершения и проверки нового. Прерванный download, битый SHA, отсутствие файлов, ошибка диска/сервера сохраняют предыдущие копии.
- Не удалять ключи восстановления, ручные архивы и чужие папки. Все удаления — только по известным именам внутри собственного каталога резервов.
- Выключенное или офлайн-устройство физически не может сохранить новый файл. После включения/возврата сети оно догружает доступные пропущенные суточные копии. Состояние показывает последний успешный день и ошибку, а не ложное «всё актуально».
- Серверный архив — существующий зашифрованный FGARCHIVE1: база, авторизация, необходимая схема, функции и связанные файлы. Старый протокол latest остаётся совместимым.
- По последнему уточнению пользователя резервы не должны заполнять диск: серверный бакет ≤512 МиБ; Windows remote replica ≤512 МиБ и auto+daily SQLite ≤256 МиБ, запас свободного места ≥1 ГиБ; Android/ТСД все backup-файлы ≤512 МиБ, запас ≥512 МиБ. В расчёт входят временные файлы и общий media cache. Проверка до записи; при нехватке новый резерв останавливается с ошибкой, предыдущие хорошие копии сохраняются. Ручные и чужие файлы не удаляются.
- Перенос на VPS отложен прямым ответом пользователя «Пока без покупки VPS». Сервер не заказывать, пробный период не включать, DNS не менять. Работа только над резервами действующей системы.
- Для совместимости JSON полного архива сохраняет `tables` с workshop_* и auth.*, а остальные public таблицы — в `project_tables`. Полная проверка использует объединение обоих наборов; manifest.table_counts относится к объединению. `export_scope=full-project`. Старые readers сохраняют весь зашифрованный архив, даже если валидируют лишь прежний набор таблиц.

## API (владелец файлов — root)

POST /functions/v1/fastgo-backups, прежний JSON body с action и параметрами, ответы {data: ...}. Не включать сырые AES-ключи, пароли или JWT в ответы/журналы.

Обычные Windows/Android устройства используют Bearer текущего аккаунта и прежние device_id/device_token. ТСД без пользовательского Bearer использует свою **действующую аппаратную** пару device_id/device_token; сервер сверяет workshop_warehouse_devices, родительскую разрешённую станцию и активного создателя. У аппаратного токена нет доступа к initialize/tick/status/секретам. Его архивы только зашифрованные.

register: app = desktop | warehouse | android | tsd; host — безопасная краткая метка устройства. device_id UUID, device_token — прежняя пара UUID длиной72. Windows-владелец сохраняет прежнюю RSA-идентичность. Android может прислать SPKI RSA2048 public_key base64; сервер принимает ключ восстановления лишь от интерактивно авторизованного owner/developer, никогда от аппаратного ТСД. В ответе registered и recovery_key.

Новые операции:

1. **history** → {policy:{version:2,retention_days:7,time_zone:'Asia/Yekaterinburg'},snapshots:[{id,day,created_at,completed_at,source_version,sha256,bytes,key_id,media_expected}, ...]}. Только завершённые суточные копии, от новой к старой, максимум7 различных дней. Пустой список не разрешает клиенту очистить локальные архивы.
2. **snapshot**, snapshot_id → прежняя структура latest плюс day и completed_at: id, created_at, source_version, sha256, bytes, key_id, key_boxes, media, media_expected, url. media содержит id,sha256,bytes,key_id. URL временный и выдаётся только для проверенного приватного бакета.
3. **media**, id и snapshot_id → прежний ответ id,sha256,bytes,url; принадлежность проверяется по выбранному завершённому снимку, а не только текущему newest.
4. **receipt** остаётся совместимым; допускает day/retained_days для отчёта, но verified=true не выставлять без фактической проверки восстановления. Подтверждение целостности зашифрованных байтов и проверка расшифрованной базы — разные факты.

latest без snapshot_id сохраняется для старых клиентов. Пока history не развёрнут, клиент при определённом 400/404 unknown action может работать со старым latest, но не объявлять 7 суточных копий готовыми и не удалять историю. Ошибка500/сеть не является поводом придумывать пустую историю.

## Windows (отдельный исполнитель)

Файлы: warehouse-desktop/backup-replica.cjs, desktop/store.cjs, Windows lifecycle/scheduler и относящиеся тесты. Получение 7 history/snapshot с проверкой хеша, атомарной записью, прежними приватными ключами и общим кэшем media. Новая завершённая локальная копия разрешает ротацию до7 успешных дней. Перед удалением media считать ссылки всех оставленных локальных манифестов. Не удалять файл, на который ссылается сохранённый архив.

Ежедневно сохранять также локальную SQLite с несинхронизированной очередью. Существующий короткий восстановительный буфер и ручные копии не ломать. Фоновые проверки/догрузка не блокируют обычную работу; обновление и активное резервирование не стартуют одновременно. Сохранить состояние последнего успешного дня и понятную ошибку. Новые приложения не публиковать до интеграции серверного контракта.

## Android и ТСД (отдельный исполнитель)

Файлы только warehouse-android/** и относящиеся новые tests/scripts. Phone: использовать сохранённую штатную сессию через существующее защищённое хранилище, обновление access token — существующим способом. ТСД: аппаратные реквизиты SecurePrefs. JobScheduler с сохранением задания после перезагрузки, сетевое условие, суточный запуск и догрузка после возвращения сети; не просить лишние разрешения на внешнее хранилище/уведомления.

Файлы в приватном каталоге приложения: временная запись → проверка размера/SHA256 → fsync/rename → завершённый манифест. Семь успешных суточных дат, общий media-кэш и сохранение последнего хорошего архива при сбое. Ключи не хранить открыто; RSA владельца — Android Keystore. Нельзя выдавать наличие ciphertext за проверенное восстановление plaintext. Состояние доступно из приложения и через receipt. Для ТСД учесть собственную несинхронизированную очередь; не закрывать/подменять рабочую SQLite ради копирования.

## Проверка и выпуск

Один связный пакет: восемь успешных дней дают7; прерванный восьмой день сохраняет предыдущие7; повтор дня не дублируется; ошибка/пустая история не удаляет копии; восстановление выбранной тестовой копии; догрузка после офлайна; отзыв аккаунта/ТСД не даёт доступа; прежний latest совместим. Не повторять сервисные/платёжные сценарии, не проводить реальные оплаты/складские операции.

Root владеет supabase/functions/fastgo-backups/**, supabase/workshop-backups.sql и server/migration/hosting. Исполнители не меняют эти файлы и не отправляют сообщения друг другу. Результаты — отдельные JSON в outputs соответствующих пакетов; один короткий итог сюда после реально готового пакета. Код готовится параллельно, публикация — после общей проверки контракта.
