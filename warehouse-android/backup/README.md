# Суточные копии Android phone и нативного ТСД

Общий код подключён к обоим приложениям через `sourceSets`, новых разрешений ОС нет. Версии и каналы обновления не меняются этим пакетом.

* JobScheduler: сохранённое сетевое задание каждые 24 часа, догрузка при запуске/после перезагрузки и после появления сети. ТСД имеет отдельное суточное задание без сетевого условия для своей локальной очереди.
* В приватных файлах хранятся FGARCHIVE1 ciphertext, SHA-256, завершённые суточные манифесты и общий media-кэш. Временный файл проверяется, синхронизируется и атомарно заменяется через Android `Os.rename`; каталог тоже синхронизируется. При пустой/ошибочной истории и несовместимом `history` ротации нет. До появления семи завершённых серверных дат прежняя история сохраняется.
* Лимит управляемых файлов одной установки — 512 МиБ, свободный запас тома — ещё 512 МиБ. Учитываются все аккаунты, медиа, очередь и partial-файлы. Перед загрузкой/временной записью есть резервирование бюджета; перед чтением очереди — проверка оценки размера. Если семь копий не помещаются, старые хорошие копии сохраняются, интерфейс показывает последний день и ошибку. Другие приложения недоступны из Android sandbox; общий запас свободного места проверяется на томе.
* Phone переносит существующую WebView-сессию в AES/Keystore и удаляет прежний plaintext. Подготовка только Android-бандла направляет штатный refresh в общий native механизм. Сеть не держит блокировку чтения/выхода из аккаунта; результат refresh сохраняется с проверкой поколения и прежнего токена. Запоздалый callback не восстанавливает завершённую сессию.
* Ключ восстановления владельца — RSA2048 Android Keystore. SPKI передаётся при регистрации только после проверки роли через API. При поддержке OAEP-SHA256/MGF1-SHA256 проверяются AES-GCM, структура базы (`tables` плюс необязательные `project_tables`), восстановление в SQLite в памяти и все медиа. Неподдерживаемый Keystore даёт честный `verified=false`; private RSA/AES-ключи не экспортируются.
* ТСД использует только текущую аппаратную пару из SecurePrefs, без Bearer, без owner public key. Его серверные receipt всегда `verified=false`. Локальная очередь читается единой WAL-совместимой транзакцией (`kv/docs/catalog`), шифруется отдельным AES/Keystore-ключом и проверяется восстановлением в отдельной SQLite в памяти. Рабочая база не закрывается и не подменяется ради копирования.
* Статус: «Резервные копии» в профиле/мобильном «Ещё» телефона и на главной ТСД. Показаны последний успешный день, фактическое число копий, ошибка и различие ciphertext/проверенного восстановления. Ошибка места отображается даже если новый status-файл уже нельзя записать.

Направленный host/API23 пакет:

```
node scripts/check-android-backups.cjs
```

Он исполняет настоящий Java replica/AES parser с тестовым сервером, проверяет ротацию, partial/corrupt/offline/catchup, legacy, media references и low-space/oversize; компилирует новые классы против Android 6/API23 и проверяет JS-интеграцию. Кэш зависимостей и результат находятся в игнорируемом `backup/build/check/`.

После интеграции нужны **только** направленные Android runtime tests `ru.fastgo.mobile.BackupRuntimeTest` и `ru.fastgo.tsd.BackupRuntimeTest` на чистых тестовых установках. Они проверяют реальные Keystore/SQLite/JobScheduler. В этом пакете не запускались Gradle/APK/устройства, не подтверждены реальная перезагрузка, Doze, физический ТСД и доступ к развёрнутому history. Не публиковать приложения до общего серверного/нативного gate. Полный перенос на VPS отложен; используется прежний API.
