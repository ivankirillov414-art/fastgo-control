# Восстановление FastGo по коду

Клиент: «Забыли пароль?» → почта → код → новый пароль с повтором → обычный вход. Проверка кода: Supabase /auth/v1/verify, type=recovery. Отправка: /auth/v1/recover с redirect_to в query. Одноразовые токены не сохраняются в localStorage. После смены пароля временная сессия закрывается; пользователь вводит пароль в обычной форме. Поля размечены username, one-time-code, new-password и current-password. Предложение сохранить пароль управляется iOS/браузером.

Проверка доверенного устройства для owner/developer сохранена. Код не является способом обхода этой проверки. При открытии ссылки вместо кода временный токен сразу удаляется из адресной строки. Обычный вход и роли не изменены.

## Осталось включить шаблон письма

Клиент поддерживает код, но реальная отправка числового кода требует сохранения шаблона в настройках Supabase. Файл supabase/templates/recovery.html содержит готовый текст с {{ .Token }}. Его добавление в GitHub само по себе НЕ меняет настройки Auth.

Supabase project oqgpjfikjpcplnxueoki → Authentication → Email Templates → Reset password: тема «FastGo — код восстановления пароля», содержимое из recovery.html. Если шаблон редактируется визуальным редактором, переключиться на HTML. Остальные шаблоны и параметры аутентификации не менять. До переключения старое письмо со ссылкой продолжает работать; клиент показывает подсказку об этом.

Для завершения проверить фактическую доставку письма на почту пользователя и восстановление на его доверенном устройстве. Не запрашивать у пользователя код или пароль в чате. Браузерные тесты используют вымышленные данные и не доказывают доставку реального письма. Лимит отправки писем контролирует Supabase; частые повторы его не снимают.
