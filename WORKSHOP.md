Продолжен существующий `ivankirillov414-art/fastgo-control`, база FastGo OS
`oqgpjfikjpcplnxueoki`. Новый проект базы, копии клиентов и замена розничного

## Сценарии

- Ремонт: приёмка → назначение → диагностика → работы/запчасти → согласование
  текущей стоимости → ремонт → проверка → готов → оплата → выдача → акт.
- Хранение: приёмка с тарифом/датами → место → хранится → при необходимости
  продление или связанный ремонт → к выдаче → оплата → выдача → акт.
- При сохранении списка **установленных** запчастей склад меняется в той же
  транзакции. Это не предварительная смета запчастей и не резервирование.
- Удаление установленной складской позиции возвращает количество на склад.
- Повторная приёмка, платёж, движение склада и продление используют ключи
  идемпотентности. Ключи повторного платежа не означают реальный эквайринг.
- CSV открывается в Excel; пользовательские строки защищены от формул.
- Голосовой комментарий доступен мастеру и менеджеру при поддержке
  SpeechRecognition браузером: распознанный текст проверяется перед вставкой.

## Права

| Роль | Возможности |
| --- | --- |
| Владелец / администратор | Все операции; сотрудники, прайс, реквизиты, возвраты, повторное открытие |
| Мастер-приёмщик / менеджер | Приёмка, назначение, согласование, складские движения, оплаты, выдача |
| Мастер | Назначенные ремонты, диагностика, работы/запчасти, проверка, фотографии; чтение склада и прайса |

Роли проверяются по `workshop_members`, а не пользовательским метаданным JWT.
Новые сотрудники создаются через администрирование по email и паролю,
без отправки приглашения или сообщения. Существующие владельцы сохранены.

## Развёртывание

Статическая точка входа: `workshop.html`. Сборщик и установка npm-пакетов не
требуются. База общая с текущим FastGo, секретный ключ в браузер не передаётся.

1. Применить `supabase/workshop-schema.sql`, затем `supabase/workshop-queries.sql`.
   Скрипты добавляют поля/таблицы; исходные заказы, остатки и документы сохраняются.
2. Развернуть `fastgo-workshop-api` из одноимённой папки. `verify_jwt=false`
   установлен намеренно: тело функции проверяет токен через Auth `/user` и
   активное членство на каждом запросе, включая запросы файлов.
3. Опубликовать статические файлы на текущем хостинге с сохранением относительных
   путей и перейти на `workshop.html`.
4. В том же выпуске обновить `fastgo-storage-api` и `fastgo-service-api`
   защищёнными версиями из `supabase/functions/`. Это закрывает старые публичные
   способы чтения/изменения тех же данных. Старые экраны после этого работают
   только через перенаправления нового выпуска.

Добавочные таблицы и два RPC доступны только `service_role`. RLS включён;
прямой доступ anon/authenticated к `service_repairs` отозван. Старые таблицы
аренды и Shadow Army не изменялись. Нельзя считать защиту завершённой,
пока старые API не обновлены вместе с фронтендом.

## Что требует реальных данных или отдельной интеграции

- В базе заполнено имя ИП Кадырмаев Расим Ильгизович, но отсутствуют ИНН,
  ОГРНИП и адрес. Для документов предусмотрена форма реквизитов и явное
  предупреждение о незаполненных полях. Юридическая проверка условий договора
  не входила в эту доработку; ранее использованные условия сохранены.
- Запись оплаты отражает принятые деньги; приложение не проводит платёж,
  не пробивает кассовый чек и не выполняет возврат через банк.
- Telegram/VK, бронирование аренды, старый сервисный бот и розничный магазин
  сохранены. Новая мастерская не отправляет сообщения клиентам автоматически.
- Активный заказ прежнего сервиса можно продолжить кнопкой «Продолжить в мастерской».
  Клиент, техника и стоимость переносятся один раз. Исходник сохраняется;
  прежний Telegram-бот не синхронизирует последующие изменения новой карточки.
