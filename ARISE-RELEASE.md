# ARISE — подготовленная доработка

Состояние на 10 сентября 2026 года: код подготовлен в отдельной ветке. Действующий сайт, функции и база данных не изменены. Это кандидат на релиз, не подтверждённый production-релиз.

## Что изменено

- `achievements.html` стал самостоятельной страницей. Удалена зависимость от загрузки исторической HTML-страницы через `document.write`.
- Единый интерфейс: персонаж, навыки, квесты, мир, настройки. Сохранены тёмно-фиолетовая тема и исходное изображение портала.
- Сохранены исходные 37 узлов Fusion, их индексы и награды. Добавлены 15 узлов английского с отдельной последовательностью разблокировки.
- Уровень персонажа, полосы XP и деревья рассчитываются из серверного прогресса. Отметка «изучено» не начисляет опыт.
- Личный ключ текущего браузера сохраняется; предусмотрены локальный кеш прогресса и экспорт/восстановление приватной резервной копии.
- Добавлены доказательства, история проверок, понятные ошибки, повторная отправка после отклонения, ручная синхронизация.
- Дейлики используют дедлайн 23:00 по Оренбургу, создаются с конкретным результатом; повторение можно выбрать при создании.
- Подготовлены шесть серверных обработчиков. Проверка изображения получает реальные требования каждого задания. Узлу Fusion № 3 нужны и STL нужных габаритов, и CAD-скриншот.
- Файлы ограничены 20 МБ; большие изображения кодируются частями. Недоступность AI не превращается в фиктивное подтверждение.
- SQL пересчитывает награды без повторного начисления и защищает записи транзакционными блокировками. Ранее принятый результат не понижается новой неудачной попыткой.
- Удалены общий fallback-ключ в PWA и автоматический запрос разрешения на push. Кеш касается только ресурсов ARISE, не соседних приложений FastGo и не приватных API.

## Проверка

Запуск из корня репозитория, Node.js 22+; установка пакетов не нужна:

```sh
node --test tests/arise.test.mjs
node --check arise/app.mjs
node --check arise/core.mjs
node --check supabase/arise-functions/_shared/server.mjs
```

Тесты проверяют чистую логику и HTTP-обработчики с подменёнными ответами БД/AI. SQL сверялся с актуальной схемой Personal RPG и статически проверялся на сохранение таблиц/строк и соответствие наград. Он НЕ запускался на PostgreSQL. Не выполнены браузерная проверка, реальные загрузки, интеграционное тестирование Supabase, проверка доставки push и офлайн-установки на телефоне. Нельзя считать эти сценарии подтверждёнными только по unit-тестам.

## Блокеры выпуска

1. **Идентификация.** Существующий API принимает `x-device-id` как единственный ключ доступа. При чтении текущих политик обнаружено анонимное чтение `quest_evidence` и объектов хранилища, а также анонимная вставка доказательств. Подготовленный SQL закрывает эти правила, но не отменяет возможную прежнюю утечку ключей и не устанавливает подлинность старых подтверждений. До публичного релиза нужны Supabase Auth, привязка владельца и согласованный перенос существующего прогресса с отзывом старых ключей. Не следует автоматически считать предъявление старого ключа достаточным доказательством владения.
2. **Ручная проверка.** PDF, аудио, видео и большинство CAD-файлов сохраняются как ожидающие проверки. Старый защищённый `review-quest-evidence` существует для узлов навыков, однако панель проверяющего, ручная проверка дейликов и переоценка после сбоя AI в этой доработке не реализованы. Устные задания английского поэтому не закрываются одним скриншотом. Нельзя обещать полностью автоматическое прохождение всех веток.
3. **Физическая ветка.** `hunter/` сохранён как эксперимент. Реального распознавания позы/повторов и интеграции с XP нет; симуляция не является выполнением задания.
4. **Повторяемые квесты.** Выбор повторения при создании реализован, но управление уже созданными шаблонами (пауза/редактирование) ещё не добавлено.
5. **Приёмка и публикация.** Требуются согласованные браузерные/интеграционные проверки, применение серверной части и отдельное разрешение на публикацию существующего сайта.

## Серверный комплект

Только проект Supabase **Personal RPG**, `cnjmbzobtvfjqhedhwpj`. Не применять к FastGo OS. Секреты не входят в репозиторий: обработчики используют штатные `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`. `ARISE_REVIEW_MODEL` опционален; прежнее имя модели оставлено как fallback и требует проверки доступности перед релизом.

`supabase/arise-release.sql` — подготовленный транзакционный SQL, не применённая миграция. Он не удаляет записи и таблицы. `supabase/arise-functions/` — отдельный набор исходников, а НЕ текущая конфигурация развёртывания соседних FastGo-функций. Каждый `index.ts` импортирует общий обработчик и учебную программу из `arise/curriculum.mjs`; комплект нужно собирать с сохранением этих относительных путей.

После устранения блокеров и резервного копирования: проверить SQL в тестовой базе, применить изменения к Personal RPG, развернуть согласованные обработчики с новой аутентификацией, проверить сохранение реального прогресса, затем публиковать frontend. Не выкладывать только HTML поверх старых функций: контракты старой проверки и ежедневных квестов отличаются. Старые anon-политики не восстанавливать даже при откате интерфейса.

Изменения не затрагивают аренду, магазин, мастерскую и их серверные функции. Старые ARISE runtime-файлы сохранены для истории, но новая страница их не загружает.
